# 更新推送与公告中心

终端管理打包器（packer）、主题中心（theme-center）、影视中心 / APP 后台（operations）。本批实现终端页面、持久化数据、签名接口与 Node 接入模块；三个现有产品的界面、后台轮询、安装执行器与升级后重启确认，需在各自项目中接入。

## 实际使用流程

1. 在版本中心上传真正的软件安装包，选择产品、平台、架构、渠道、版本和升级说明，审核后发布。主题模板、APP 源码与产品源码不当作软件安装更新推送。
2. 更新推送中选择已发布的软件版本，填写标题说明、客户范围、生效与截止时间，保存草稿，确认后发布。一个推送绑定一个产品版本；客户不勾选表示所有客户。
3. 公告中心支持普通消息、顶部通知、弹窗、维护公告，可选三个产品、指定客户、定时生效和要求确认。公告可以关联单个产品的软件版本；关联公告本身不改变该版本的更新分发范围。
4. 可编辑草稿、复制通知、查看真实回执、撤回通知。已发布正文不能直接改动；需要新内容时复制为草稿重新发布，避免客户确认与内容不对应。撤回后的通知不能再次发布。
5. 未接入的产品不会产生回执。收到、已读、确认、下载、安装中、失败、安装成功分别记录；终端不会把检查更新或下载完成计作安装成功。

## 版本分发规则

原有未关联推送的软件版本继续通过通用更新清单分发。一个版本首次关联推送草稿后，即改为受推送范围管理：只有当前已发布、生效、未过期且客户和产品匹配的推送允许自动分发该版本。草稿、撤回、过期或尚未生效的推送不允许自动分发该版本。这个规则避免客户通过通用更新接口绕过定向推送。

撤回推送停止后续自动提示，不撤销已安装的软件，也不取消已发布版本的授权手动下载。需要禁止下载时应在版本中心撤回版本。强制更新只是签名策略标记；产品需实现空闲检查、提示和安装执行器，不应打断打包、导出或其他正在进行的任务。

## 产品接入接口

使用已激活的客户 Key 和激活 ID，HTTPS 请求；本机开发可使用 localhost。每次请求携带 Authorization: Bearer <客户Key> 和 X-Hetun-Activation: <激活ID>，不要使用管理员账号或签名私钥。

| 接口 | 用途 |
| --- | --- |
| GET /v1/notifications | 签名公告与更新推送，包含当前激活身份对应的接收状态 |
| POST /v1/notifications/ack | 接收、阅读、确认或安装过程回执 |
| GET /v1/updates?product=packer&version=1.0.0&platform=windows&arch=any&channel=stable | 当前身份范围内的签名更新清单 |
| GET /v1/releases/<版本ID>/download | 当前授权允许的安装文件下载 |

回执示例：

~~~json
{"notificationId":"通知ID","revision":1,"status":"read"}
~~~

安装成功必须在新程序启动并确认实际版本后发送：

~~~json
{"notificationId":"推送ID","revision":1,"status":"installed","version":"1.1.0"}
~~~

通知支持 received、read、confirmed；更新还支持 downloaded、installing、installed、failed。失败可提供不超过 300 字的 message。回执只接受本客户、本激活产品、可见通知和准确修订；installed 版本必须与关联版本相同。重复回执不会把安装成功降级，迟到的旧版本回执不会覆盖设备的新版本状态。

## 接入模块与安装边界

integrations/delivery-client.mjs 导出 createDeliveryClient，传入固定终端地址、公钥、客户 Key、activationId、product、version、platform、arch 和 channel。

- notifications() 验证 Ed25519、签发地址、产品、激活身份和响应时间，首次收到时自动提交 received；实际展示或确认后由产品调用 ack。
- updates() 获取和验证更新清单；downloadUpdate(外部绝对目录) 重新获取签名清单，下载并校验长度及 SHA-256。
- verifyBeforeInstall(文件路径, release) 安装前再次检查本地文件；产品还应验证平台签名、安装包类型和兼容性。
- ack(通知, 状态, 补充字段) 上报真实结果。模块不会自行执行安装器，不会伪造 installed。

产品接入应支持启动检查、手动检查和周期检查；普通更新由用户确认后安装，忙碌时等待空闲。安装前保存待确认的推送 ID / 修订和目标版本，新程序启动核对成功后回报。凭据、下载包、安装日志与待发送回执均应放在外部运行目录。离线重试队列、Windows/macOS/Linux 安装与重启流程由产品实现。

## 离线与迁移

离线客户无法即时收到新公告、撤回或更新；恢复网络并检查后取得新状态。签名响应有效时间为十分钟；客户端时钟应正常。通知数据、推送与回执已纳入整包加密迁移；迁移继续保留原终端签名身份。终端地址切换遵循现有签名地址迁移协议，接入模块不单独发现新地址。

本机网页能管理推送，不等于三个已安装客户端已完成自动更新。产品接入验收必须包含真实安装包升级、文件签名、任务空闲等待、失败恢复、重启后的准确版本回执。
