# 服务器迁移与授权地址管理

河豚终端保存三个产品的授权身份、版本资源及客户记录。本次实现终端侧迁移控制和签名通知接口。打包器、主题中心、影视中心的客户端自动接收、离线缓存、切换地址、更新及回执执行仍需分别接入，不能把终端接口存在当作这些客户端已完成。

## 一包迁移

旧服务器在“部署与迁移”开启迁移，输入当前管理员密码，设置一个迁移密码，下载 `.hetun`。新服务器安装终端并设置初始管理员密码，选择包、输入迁移密码，先检查摘要再确认导入。成功后使用旧管理员密码登录。

包包含 data.json、admin.json、Ed25519 私钥/公钥、被版本或任务成品记录引用的完整文件：客户、授权 Key 的哈希、绑定、策略、Git 绑定、三产品版本与源码、主题、安装包、任务、版本历史及云端元数据记录。Key 原明文不可从哈希恢复，客户原 Key 继续有效。应用日志、临时传输文件、Docker 配置、部署目录、旧机器端口及证书不放进包；这些机器设置按新环境重新生成。

新版 HETUNM02 格式采用 scrypt + AES-256-GCM + gzip，流式处理文件，整包上限 8 GiB，避免旧版 64 MiB 业务文件限制。兼容导入 HETUNM01。先完整认证解密，再检查业务关系、密钥配对和每个文件的 SHA-256/长度。导入仅允许空白实例；文件换入以日志控制，进程中断时启动恢复原完整快照，成功后清除管理员会话。临时文件位于外部运行目录，权限限制；失败立即清理，重启清除残留传输目录。

导出需要足够临时空间，导入同时需要上传包、解密内容、文件检查及换入副本，建议预留业务文件累计大小的四倍空间。超过 8 GiB 使用 Linux 完整备份恢复。加密包和密码分开保管；遗失密码无法解密。私钥自动在包内，用户不用分别搬运，但丢失原私钥会让已有客户端无法验证新身份。

## 迁移开关

正常 → 旧服务器 preparing → 导入后新服务器 restored → 正式域名核验 → completed。可以主动取消本机迁移以恢复修改；取消不会自动恢复之前取消的构建。

开始前须等待正在运行的构建完成，等待中的任务会取消。迁移期间冻结管理员业务变更、新设备激活、新构建及节点领取，保留登录、查看、迁移控制、已有设备授权复查与签名配置读取。宽限 1–30 天，签名 lease 到期仍不能超过客户授权到期时间，已停用/到期授权不能因迁移变成有效。迁移开关不自动停止网站、不修改 Cloudflare，也不自动取得 DNS 管理权限。

迁移必须只有一个正式写入端。旧终端保留迁移冻结直到切换成功；新服务器完成后停用旧终端，不能让两台相同私钥实例同时发布策略。导出后的旧端新回执不会自动复制到已导入的快照，新端以实际后续回执更新；“尚未确认”可能是离线或未接入。

## 换服务器与换域名

保留同域名最直接：导入原数据/密钥，DNS 指向新服务器，接通 HTTPS，新服务器验证正式域名并完成迁移。

更换域名时：先接通新域名与 HTTPS，恢复原密钥；旧终端验证并下发新地址，客户签名确认后迁移。也应保留旧域名或备用入口代理到新终端一段时间，避免长期离线客户再上线无法找到授权中心。迁移期间按上述单写入顺序配置，禁止旧端在新端完成后再发布冲突策略。备份快照之后产生的地址配置需在新端核对并保存。所有旧入口都失效且软件仅知道旧地址时，无法单靠一个面板按钮让离线设备获知新域名。

“验证并下发地址”要求无端口、无路径、无凭据的公网 HTTPS 域名。随机挑战校验同一 Ed25519 公钥身份、回应地址、随机数及签发时间；不接受重定向，公网探测拒绝内网 DNS 结果并固定解析地址，限制响应大小与连接等待时间。备用地址最多三个，也逐个验签。错误不会保存成功状态。完成迁移仅允许在 restored 新实例，当前访问地址须等于已验证正式地址，最近验证不超过 15 分钟。

## 接口与接入约定

管理员（Cookie + Origin + CSRF）：GET /api/migration/status；POST /api/migration/start（graceDays、message）；POST /api/migration/cancel；POST /api/migration/address（primary、fallbacks）；POST /api/migration/finish；原有 /api/migration/export、/import 保留。导入预览不会修改数据；带摘要 keyId 的 confirm 再上传确认。上传支持流式 8 GiB，反向代理的请求大小/超时设置也须匹配。

公共 GET /v1/terminal-identity?nonce=随机数返回 Ed25519 封套：type=hetun-terminal-identity、nonce、origin、keyId、iat，仅公开签名身份，不公开业务信息或私钥。

客户 GET /v1/terminal-config 需要原 Key 和 X-Hetun-Activation。配置封套包含 type=hetun-terminal-config、schemaVersion=1、keyId、revision、primary、fallbacks、phase、migrationId、message、graceUntil、issuedAt、retryAfterSeconds。原 activate/check 响应也包含 terminalConfig。客户端应验签原始 payload 字节，固定原公钥，检查配置版本与迁移身份，验证新端可连接后持久化地址；允许签名配置指定的新 issuer，不能直接信任任意服务端 URL。断网按现有签名凭据与宽限处理，有效期与撤销规则不可绕过。

POST /v1/terminal-config/ack（revision、migrationId、status=received/connected）须携带同一客户凭据。只能更新自身 binding，配置版本过期拒绝。connected 回执必须实际到达正式地址的终端，服务端记录接收地址与时间，不信任客户端提交的任意目标地址。这个请求能证明持凭据请求到达，不能证明不可篡改的硬件身份或全部客户端功能正常。

回执属于接入协议，现有三个产品尚未执行它。界面明确标注此边界，不自动制造“已连接”记录。未确认、离线、未接入与失败分开解释。授权地址切换不等同 DNS/证书部署；服务器地址绑定仍需要真实网络入口，不能抢占已有网站端口。
